# 2. Global UX Principles

The FidNext website should follow these principles across all pages.

## 2.1 Business First

The website should communicate business value before presenting technical details.

---

## 2.2 Problem Before Solution

Visitors should first recognize their business or technology challenge before being presented with FidNext services.

---

## 2.3 Clarity Over Complexity

Every page should answer:

* What is this?
* Who is it for?
* Why does it matter?
* What should I do next?

---

## 2.4 Proof Before Strong Claims

Wherever possible, claims should be supported by verified:

* Case studies
* Client results
* Testimonials
* Experience
* Technology expertise
* Certifications
* Partnerships

Unsupported claims must not be presented as facts.

---

## 2.5 One Primary Conversion Goal

The primary website conversion should remain:

**Book a Free Consultation**

Secondary CTAs may support exploration without competing with the primary conversion.

---

## 2.6 Progressive Disclosure

Visitors should see the most important information first.

Detailed technical information should be available deeper within the page for visitors who want it.

---

# 3. Global Page Structure

Most major pages should follow a consistent structure:

```text
Page Introduction
      ↓
Problem / Context
      ↓
Value / Approach
      ↓
Capabilities / Services
      ↓
Proof / Evidence
      ↓
Process / How It Works
      ↓
CTA
```

Not every page requires every section.

Sections should only be included when they provide meaningful value.

# 25. Mobile Page Architecture Principles

Every page must be intentionally designed for mobile.

## Mobile priorities

1. Clear hierarchy
2. Short readable content blocks
3. Strong typography
4. Thumb-friendly CTAs
5. Simplified navigation
6. Easy forms
7. Minimal unnecessary animation
8. Fast loading
9. Accessible controls
10. Preserved conversion path

Mobile should not simply be a compressed desktop layout.

# 26. Accessibility Considerations

Page architecture must support accessibility from the beginning.

Requirements include:

* Logical heading hierarchy
* Semantic page sections
* Keyboard-accessible navigation
* Accessible forms
* Clear focus states
* Meaningful link labels
* Appropriate contrast
* Alternative text for meaningful images
* Reduced-motion consideration
* Screen-reader-friendly structure

These requirements will be refined by later QA stages.

# 31. UX Decision Rules

## Rule 1 — No Unsupported Claims

UX architecture must never force the business to make unsupported claims.

## Rule 2 — No Thin Pages

Do not create a page simply to increase the number of website pages.

## Rule 3 — Conversion Must Be Natural

Every page should provide a logical next step.

## Rule 4 — Problems Should Be Recognizable

Visitors should be able to identify their challenge quickly.

## Rule 5 — Services Should Explain Value

Service pages should communicate outcomes and problems, not only technical deliverables.

## Rule 6 — Proof Must Be Real

Only verified evidence may be presented.

## Rule 7 — Mobile Is First-Class

All architecture decisions must work on mobile.

## Rule 8 — Keep the Experience Premium

The structure should support a sophisticated, strategic technology-company experience rather than a generic agency template.
